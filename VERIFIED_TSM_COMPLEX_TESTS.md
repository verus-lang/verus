Replace those presence assumes by explicit requires in the extracted failing model, and continue expecting variant safety failures: no new trust.

Critical fidelity point: state-machine relation tests distinguish weak relations (an unproved assertion yields implication, allowing arbitrary later states if false) from strong relations (all assertions conjunctively true). The proof-producing resource API must require checked strong/safety enabling; it cannot preserve an unsafe original assume(false) proof while remaining axiom-free. Keep original weak/strong syntax semantics as pure diagnostic reference definitions, and explicitly label any strengthened executable/resource enabling API rather than silently changing the reference relations.

Suggested sequencing: (1) ordinary relation/match + assert-require-let/count (ready backend), (2) complete bind finite/infinite, (3) complete refutable finite/infinite with exact storage packing and twenty isolated client failures, (4) complete persistent optional/bool/count/map cases after canonical general operand frontend, (5) complete general special relation diagnostics plus explicitly enabled resource histories, (6) scoped indexed-update relation cases and remaining parser/safety negatives. Each slice needs a separate reviewer and actual example checks; no full test suite.
