# Branch conditions without test coverage

This file lists the branch conditions of the verifier crates (vir, rust_verify, air, builtin_macros, state_machines_macros) that no test covers in the MC/DC sense, and for each one the reason. Line numbers refer to the base of this branch, upstream commit 09d09ee2.

A decision is a boolean expression built from `&&`, `||` and `!` in the source: an `if` or `while` condition, a match guard, a `let` initializer, a return value or an argument. Its atoms (conditions) are the operands that are not themselves built from those operators, numbered from 0 in source order. An atom is covered when two recorded evaluations of its decision have different outcomes and different values of that atom, while every other atom has the same value in both or is not evaluated in one of them (unique-cause MC/DC; an atom that `&&` or `||` skips counts as not evaluated). A covered atom is a condition that the tests show to change the decision by itself. Code inside macro invocations (34 `&&`/`||` operators, for example inside `assert!`) is not counted.

Condition coverage counts atoms observed both true and false; decision outcomes count the outcomes observed, two per decision. The 209 infeasible atoms are those classified UNREACHABLE, PINNED, COUPLED-INFEASIBLE or FEATURE-GATED below; the OPEN atom stays in the denominator.

The list was produced and checked as follows. The atoms left after the tests were first collected on the earlier commit 1d72e6d, where test programs were written for each uncovered atom in three rounds. For each atom that no program covered, an argument names the invariant or the earlier check that excludes the missing evaluation, with file and line. Three independent reviews re-derived each argument with complete enumerations of the relevant constructors, callers and assignments; a fuzzer ran 97,100 programs aimed at these atoms and produced none of the missing evaluations; for 37 atoms a Lean model of the relevant code proves the missing evaluation impossible in the model (the proof holds for the model; the model's correspondence to the Rust code rests on per-definition citations and, for the generated-program models, on agreement with Verus on 405 programs). Of the 253 infeasibility claims in a first version of the list, 49 were refuted by a program that produced the excluded evaluation; those atoms are covered now. The arguments were written for 1d72e6d; the 210 atoms map to 09d09ee2 with the same decision text and atoms, and the line numbers in the arguments are translated to 09d09ee2.

Classifications:

- UNREACHABLE: the needed value or the decision itself is excluded by an earlier check that rejects the program or returns first; also atoms short-circuited by a pinned atom.
- PINNED: the atom has one value whenever it is evaluated, because of an invariant of the data or a constant.
- COUPLED-INFEASIBLE: the atom takes both values, but its independence pair needs a combination of atom values the code cannot produce (complementary atoms, a repeated expression, values tied by construction).
- FEATURE-GATED: the code is compiled only with a Cargo feature that no build enables.
- OPEN: no infeasibility argument holds and no test reaches the missing evaluation.
- NOT-REPLAYED: the atom is feasible and an earlier run covered it (on 1d72e6d, or a program on 6d85179), but the test suite cannot reproduce that run or no test here repeats it; the argument column gives the reason (an environment variable, the `singular` feature, the cvc5 solver, a verifier panic, or a one-off program that was not kept).
