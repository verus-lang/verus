# Verus trust audits

`verus-trust-audit` renders a source-oriented snapshot of the code trusted by
`#[verus::trusted]`.

First ask Verus to produce a manifest:

```sh
verus --no-cheating --emit-trust-manifest crate.trust.json src/lib.rs
```

For a Cargo project, emit one manifest per verified package target into a
package-specific subdirectory (the option implies `--no-cheating`):

```sh
cargo verus verify --emit-trust-manifests trust-manifests
```

Then render it:

```sh
verus-trust-audit crate.trust.json trust-snapshot
```

The renderer copies trusted source text verbatim, replaces the body of
`#[verus::trusted(spec)]` functions with a fixed omission marker, and preserves
the necessary module, impl, trait, and `verus!` shells. It verifies source-file
hashes before rendering so that a manifest cannot accidentally be applied to a
different source tree.

Trusted items generated by macros other than the normal `verus!` syntax macro
are currently rejected because rustc does not retain a single faithful source
range for their expansion.

Because the snapshot is rendered from source text, Verus refuses to emit a
manifest if that text does not determine the trusted code:

 * Trusted code (for `trusted(spec)` functions, the signature and specification)
   may not expand a macro defined in the same crate unless the macro definition
   is itself `#[verus::trusted]`, in which case it appears in the snapshot.
   Macros from other crates, such as `verus!`, `vec!`, or vstd's macros, are
   allowed, just as references to other crates are.
 * Trusted code may not use `include!`, `include_str!`, or `include_bytes!`, and
   may not otherwise contain code whose source lies outside the item's own text.
 * Every trusted item must have a source range that can be recorded.
